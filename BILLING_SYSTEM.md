# Billing System (Система баланса и подписок)

## Концепция

Система управления подписками через баланс пользователей без встроенной обработки платежей. Платежи обрабатываются вне системы, администратор вручную пополняет баланс пользователям.

## Основная логика

- **Бесплатные пользователи** (`subscriptionType: 'FREE'`) - без ограничений по времени
- **Платные пользователи** (`subscriptionType: 'PAID'`) - работают по системе баланса
- **Когда баланс >= стоимости месяца** - пользователь активен, обычные лимиты трафика
- **Когда баланс < стоимости месяца** - лимит трафика = 0 (блокировка)

## Структура данных

### Пользователь (User)
```typescript
{
  subscriptionType: 'FREE' | 'PAID'
  balance: number                    // Баланс в условных единицах
  subscriptionStartDate: Date        // Дата начала текущего периода подписки
  nextBillingDate: Date             // Дата следующего списания (subscriptionStartDate + 30 дней)
  subscriptionStatus: 'ACTIVE' | 'INSUFFICIENT_BALANCE'
}
```

### Системные настройки (Settings)
```typescript
{
  'billing.monthly_cost': 100        // Стоимость месяца подписки
  'billing.currency_name': 'баллов'  // Название валюты для отображения
}
```

### История операций с балансом (BalanceTransaction)
```typescript
{
  userId: number
  amount: number                     // Положительное = пополнение, отрицательное = списание
  type: 'PAYMENT' | 'MONTHLY_CHARGE' | 'ADMIN_ADJUSTMENT'
  description: string               // Описание операции
  performedBy: number              // ID администратора (для PAYMENT/ADMIN_ADJUSTMENT)
  createdAt: Date
}
```

## Пользовательский интерфейс

### Что видит пользователь (subscriptionType: 'PAID'):
- **Баланс**: "250 баллов"
- **Осталось**: "2 месяца 17 дней" (250 / 100 = 2.5 месяца)
- **Стоимость подписки**: "100 баллов/месяц"
- **Статус**: "Активна" / "Недостаточно средств"

### Уведомления:
- **НЕ уведомлять** если баланса хватает на продление (>= monthly_cost)
- **Уведомлять** только когда баланс < monthly_cost:
  - "Недостаточно средств для продления подписки"
  - "Обратитесь к администратору для пополнения баланса"

## Административный интерфейс

### Управление балансом:
- Список пользователей с текущим балансом и статусом
- Кнопка "Пополнить баланс" с указанием суммы
- Кнопка "Корректировка баланса" (+ или -)
- Фильтр пользователей с недостаточным балансом

### Управление биллингом:
- **Кнопка "Пересчитать биллинг"** - запускает тот же процесс, что и daily cron job
- Показывает результат последнего пересчета (дата, количество обработанных пользователей)
- Логи всех биллинговых операций с результатами

### История операций:
- Все транзакции по балансу (пополнения, списания, корректировки)
- Фильтр по пользователю, типу операции, дате
- Экспорт в CSV для отчетности

## Автоматизация

### Daily Billing Process (раз в день + по кнопке админа):
**Запускается автоматически каждый день в 00:00 + по кнопке "Пересчитать биллинг" в админке**

1. **Обработка индивидуальных списаний:**
   - Находит всех пользователей с `subscriptionType: 'PAID'`
   - Для каждого пользователя проверяет: наступила ли дата `nextBillingDate`
   - Если наступила:
     - Списывает `monthly_cost` с баланса
     - Обновляет `subscriptionStartDate` = `nextBillingDate`
     - Обновляет `nextBillingDate` = `subscriptionStartDate` + 30 дней
     - Создает запись в `BalanceTransaction` типа 'MONTHLY_CHARGE'

2. **Обновление лимитов трафика:**
   - Проверяет всех платных пользователей
   - Если баланс < monthly_cost:
     - Ставит `subscriptionStatus: 'INSUFFICIENT_BALANCE'`
     - Устанавливает лимит трафика = 0 для всех ключей пользователя
   - Если баланс >= monthly_cost:
     - Ставит `subscriptionStatus: 'ACTIVE'`
     - Восстанавливает обычные лимиты трафика

3. **Логирование результатов:**
   - Сколько пользователей обработано
   - Сколько списаний выполнено
   - Сколько пользователей заблокировано/разблокировано

## Особенности реализации

### Блокировка через лимиты трафика:
- Вместо отключения ключей используется установка лимита трафика = 0
- Пользователь видит свои ключи, но они не работают (исчерпан лимит)
- При пополнении баланса лимиты автоматически восстанавливаются

### Типы пользователей:
- **FREE** - родственники, друзья (баланс игнорируется)
- **PAID** - клиенты (работает система биллинга)

### Гибкость системы:
- Стоимость месяца настраивается в админке
- Можно добавлять разные тарифы в будущем
- История всех операций для аудита и отчетности

## Миграция существующих пользователей

1. Всем существующим пользователям ставим `subscriptionType: 'FREE'`
2. Администратор вручную переводит нужных пользователей в `PAID`
3. Пополняет им начальный баланс
4. Устанавливает `lastBillingDate` = текущая дата
